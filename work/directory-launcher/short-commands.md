# 短命令、统一切换和默认命令跟随

2026-11-12。用户同意切换中断全部同服务旧 CLI，不区分空闲或繁忙；并选择普通命令跟随最近选择的账号。
本轮仅实现、离线验证和记录，未部署、提交或执行真实切换。私人标签和路径没有写入公开材料。

## 原生行为与本地选择

原生 Codex 读取 `CODEX_HOME`，未设置时使用 `~/.codex`。它不认识 FlipAuth 登记表或当前选择。
依据是本轮重新读取的 [OpenAI 官方配置文档](https://learn.chatgpt.com/docs/config-file/config-advanced)。
因此保持原命令固定使用其默认目录最接近原生行为；用户选择的便利性由一层可选 sh 包装实现。
包装读取当前选择、设置目录并 exec 固定的官方程序，登录、刷新和请求仍由官方 CLI 处理。

初始默认与当前选择是两个字段。默认目录登记为任意本地标签后，第一次使用它；切到第二标签后，
包装命令也启动第二标签；执行切回命令则恢复初始账号。目录与凭据均不移动。
生成包装文件不等于部署它，真实 PATH 仍未改动。

## 实际命令

| 命令 | 行为 |
|---|---|
| `flipauth codex account add primary "$HOME/.codex" --default` | 一次性登记现有默认目录；不改凭据 |
| `flipauth cod secondary login` | 首次创建 `~/.codex-secondary` 并官方登录；已有登记则直接登录 |
| `flipauth cod secondary` | 中断并退出全部可确认归属的同服务 Herdr CLI，在原 pane/cwd 重启为第二账号 |
| `flipauth cod primary` | 按同样流程切回初始账号 |
| `flipauth cc secondary login` / `flipauth cc secondary` | Claude 的对应入口 |
| `flipauth cod new secondary` | 只创建目录，不登录；日常可省略 |
| `flipauth cod status` / `flipauth cod list` | 只读当前选择/最近回执或登记列表 |
| `flipauth codex account bind-current /absolute/staging/bin/codex` | 明确生成跟随当前选择的 sh 包装；不自动安装 |

`cod`/`cc` 为日常简写；根命令的 `codex`/`claude` 也支持命名账号、新建、列表和新 status。
`*-switch` 保持旧行为，`flipauth SERVICE legacy ...` 明确进入旧快照模式。
现有根 `save`、`doctor`、`quota`、`observe` 和前置 `login` 保留兼容入口。
新命名账号命令从不回退到旧凭据快照。

新建目录使用独立最小配置并明确提示规则/插件缺失。需要继承的配置由已有模板机制准备；不自动复制真实凭据、
会话、数据库、插件状态或整个配置目录。账号标签不硬编码到公共程序。

## 切换顺序与准确完成含义

1. 在关闭任何进程前，检查目标目录、配置、CLI、登录文件存在性、服务进程、pane 归属、进程启动标识和工作目录。
2. 一次性 worker 独立于发起命令的 CLI，保存私有回执。返回受理及回执路径，不假称已经完成。
3. 向已确认的同服务 pane 发送取消，然后请求正常退出。繁忙状态也执行取消，不等待原任务完成。
4. 确认原进程退出。之后仅可向精确验证的 Codex managed daemon 发送 SIGTERM；没有 SIGKILL、重试升级或服务恢复。
5. 全部旧服务进程归零且 pane 回到 shell 后，原子提交当前选择。
6. 在原 pane、原 cwd 启动目标账号的新对话，读取新进程环境中的配置根确认目标目录。shell 命令受理本身不算完成。

`complete` 只表示所有目标 pane 中观察到使用目标 home 的同服务进程。
它不证明真实身份、登录有效、界面就绪或请求使用的实际账号，也不证明所有工具子进程的远端工作已撤销。
重启使用切换命令提供的参数，不复制旧的 resume 命令或账号特有启动参数。跨账号续接原对话未实现。

每服务两把锁各有职责：操作锁覆盖整次切换；启动门锁覆盖关闭与选择提交，并在 exec 时原子释放。
启动阶段释放启动门但继续持有操作锁，避免重启自锁，同时防止第二次切换撞入关闭/重启间隙。
相同目标重复执行，在选择与全部运行 home 均匹配时不关闭或重启。

不确定的 `/exit` 或重启投递通过进程回读判定，不盲目重发。停止失败不启动新账号。
部分重启失败保留回执和已提交的目标选择，可能留下部分 pane 已停/已启动；不会自动回滚再制造混合状态。

## 实际适用范围

自动重启覆盖能精确关联 PID 和本地 Herdr session/pane 的当前用户官方 CLI。
非 Herdr 终端或无法确认归属的同服务进程会在任何停止前阻断本次切换。
这是终端归属限制，不是闲忙限制。其他服务保持运行，不关窗口、tab 或整个 server。

无旧服务进程时直接在当前终端启动所选账号。普通跟随包装只启动当前账号，不主动关闭会话。
未接管的原生二进制仍按自身 `CODEX_HOME`/默认目录行为运行，不能宣称它已跟随 FlipAuth。
原生 shell alias、function、PATH 优先级及命令缓存仍需实际部署时检查。

## 文件与验证

本轮涉及入口、三个 Python 模块、测试、规则与文档，连同初版未提交工作超过 8 个文件：

- `flipauth`：短服务名、新命名入口、明确 legacy 入口及复用旧 daemon 只读检查。
- `lib/directory_accounts.py`：初始默认、启动检查拆分、共享启动门、current/bind-current。
- `lib/short_commands.py`：短命令、当前选择、sh 包装、一次性 worker 发起和私有回执。
- `lib/session_switch.py`：服务进程、Herdr session/pane、取消/退出/启动与真实配置根回读。
- `tests/short-commands-test.py`：真实假 CLI 进程和假 Herdr 协议。
- `README.md`、`AGENTS.md`、`KANBAN.md`、本工作目录及 `.gitignore`：接口、边界、恢复证据及隐私保护。

完整命令：`bash tests/run-all.sh`。
原始输出：[short-verification.txt](short-verification.txt)，最终汇总 `Suites/checks: 9; failed: 0`。
含 Bash 语法、六个原套件、目录 16 场景、短命令/生命周期 9 场景。
源码摘要：[short-source-sha256.txt](short-source-sha256.txt)。

新增场景证明：

- 首次短登录创建对应 home，原凭据快照不参与；长服务名也支持新建。
- 普通 sh 命令在两个账号之间跟随切换，参数中的空格、引号、美元符号保留。
- 两个繁忙假 Codex 均退出后才提交任意重启；另一个假 Claude 一直运行。
- 繁忙假 Claude 也可切换；重启受理结果丢失但进程已启动时回读成功，未重复投递。
- 退出拒绝、未知进程、缺少目标登录文件及命令冲突不会冒充成功。
- 发起切换的假 CLI 自身退出后，独立 worker 仍完成重启。
- 重复同目标及连续两次排队请求都不重复重启。

测试发现并修复：当前包装多带一层 `--`；仅锁关闭阶段会让第二次切换误入“无进程、直接启动”路径。
后者通过覆盖整个生命周期的独立操作锁解决，并有两个同时排队请求的端到端验证。
所有测试只有 fixture 子进程被取消或退出；真实代理、凭据、账号、网络配置和 PATH 未改变。
